# Epic 示例：PIL 单产品贷款申请 MVP

> 真实票：LEN-1。Epic 只讲业务 / 战略：为什么、对谁、范围、何时算成功。不放单功能验收，不放任何技术。

## 背景与问题

7 步申请目前是静态原型（步骤间假跳转、数据写死），无法真正收单。

## 业务目标

客户能用真实后端端到端提交一笔 PIL 申请并拿到参考号。

## 范围

- 做：单产品 PIL 完整申请漏斗、服务端权威校验、草稿续填、同意快照、提交幂等。
- 不做：多产品 / schema（→ P2 Epic）、审批决策（→ P3）、放款（→ P4）、催收（→ P6）、真实短信 / 征信 / 银行（留桩）。

## 成功指标

- 手机验证 → 提交 → 拿到 referenceNumber 全链路自动化用例通过。
- 刷新 / 回访可从服务端草稿断点续填。

## 包含 Story（建议交付顺序）

LEN-3 / LEN-4 地基 → LEN-2 验证 → LEN-5 试算 → LEN-6 资料 → LEN-7 提交 → LEN-8 状态。

## 跨 Story 风险 / 依赖

短信 / 征信 / 银行为外部依赖，先以 ACL 桩隔离，并行推进真集成。
