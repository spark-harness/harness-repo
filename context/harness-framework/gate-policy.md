# Gate Policy

门禁是阶段转换前的强制质量检查。

## 状态

| 状态 | 含义 |
|---|---|
| PASS | 可以进入下一阶段 |
| BLOCKED | 存在阻塞问题，不能继续 |
| WARN | 有风险但不阻塞，必须记录后续动作 |
| WAIVED | 原本会阻塞，但已按豁免规则批准 |

## 报告位置

门禁机器事实源应写入：

```text
requirements/{requirement-id}/gates/{gate-id}.gate.json
```

历史 `requirements/{requirement-id}/gates/{gate-id}.md` 只视为旧审计快照，不再生成、刷新、校验或作为阶段推进事实源。

## 最低内容

- 固定字段。
- 检查时间。
- 检查对象。
- 检查结论。
- 阻塞项。
- 风险项。
- 后续动作。
- 证据链接。
- 豁免信息。

## 判定原则

门禁不追求多，优先设置在错误代价最低的位置：意图、方案、任务和环境。

## 人工批准原则

Agent 可以准备门禁材料、执行机器检查、生成报告和指出阻塞项，但不能代表人工评审人批准阶段推进。

当门禁检查项都满足、但尚未取得人工批准时，门禁总结果必须保持 `BLOCKED`，阻塞项写明“等待人工批准”。只有人工评审人明确批准后，才允许把门禁总结果更新为 `PASS`；紧急例外必须使用 `WAIVED` 并填写批准人、原因、有效期和后续事项。

因此，`PASS` 的含义不是“Agent 自检通过”，而是“机器检查通过且人工批准完成”。

具体字段、命令阻塞、CI / MR 检查和豁免规则见 `gate-implementation.md`。
