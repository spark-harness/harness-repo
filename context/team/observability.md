# 可观测性规范

本文是日志、指标、Tracing 和告警的第一版入口。

它不是单独的新规范源。具体日志字段看 `logging.md`，指标命名看 `metrics.md`，Tracing 看 `tracing.md`。

## 最小要求

| 对象 | 要求 |
|---|---|
| 服务名 | `service.name` 必须与服务矩阵服务名一致 |
| 请求链路 | 能通过 `trace_id` 或 `request_id` 串联上下游 |
| 错误 | 错误日志、指标和 trace 使用稳定错误码或错误类别 |
| 延迟 | 关键入口和外部依赖必须有耗时观测 |
| 业务结果 | 核心业务链路必须有业务结果指标，不只看接口成功率 |
| 告警 | 告警必须有 owner、影响说明、排查入口和止血动作 |

## 设计时必须回答

- 新增或修改了哪些关键业务路径？
- 失败时评审者从哪里看到错误码和业务对象？
- 跨服务请求如何关联 trace？
- 是否新增外部依赖、队列、任务或异步消费？
- 哪些指标能判断用户或业务是否受影响？
- 告警触发后谁处理，第一步看哪里？

## 禁止项

- 用日志替代业务存储或审计。
- 在指标标签中放用户 ID、订单 ID、手机号、原始 URL、异常堆栈。
- 在 trace attribute 中放请求体、响应体、token 或 PII。
- 创建没有 owner、没有排查动作的告警。
